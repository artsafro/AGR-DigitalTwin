# Commands cheat sheet (user-facing, Russian)

Памятка для пользователя: какие слэш-команды набирать и когда. Написана по-русски намеренно —
это шпаргалка человека, не инструкция агенту. Агентские процедуры: `WORKFLOW.md`.
Команды, помеченные `*`, появляются с PR #107 (handover / takeover / hooks); до его мержа —
HANDOFF пишется по просьбе в чате.

## Дневной цикл — минимум

```
/takeover*  →  работа  →  /handover*  →  /clear  →  /takeover*  →  …
```

Один чат на задачу. Контекст сбрасывается `/clear`, папка worktree и ветка остаются.
Новый чат — только для новой задачи от `main` (галочка worktree создаёт ветку сама).

## По моменту работы

### Начало большой темы (раз в недели)

| Команда | Когда | Что даёт |
|---|---|---|
| `/grill-me` | Есть идея, нет плана | Агент задаёт вопросы, пока не вытащит цель, границы, решения. Выход — план (`docs/HARNESS_PLAN.md` родился так) |
| `/grill-with-docs` | План уже есть, новый чат | Сверяет понимание плана агентом с твоим; находит дыры |
| `/to-tickets` | План утверждён | Режет план на тикеты с критерием «готово» → доска / issues |

### Начало сессии

| Команда | Когда | Что даёт |
|---|---|---|
| `/takeover`* | Новый чат или после `/clear` | Читает `HANDOFF.md`, `PROJECT_STATE.md`, доску; сверяет с git; перечисляет незакрытое; **предлагает**, что взять, и ждёт «да» |
| `/next`* | Нужен просто следующий тикет | Берёт верхний из Ready, создаёт ветку, двигает в In progress |
| `/agents` | Субагент не подхватился | Список субагентов, видимых в сессии |
| `/doctor` | Что-то не загрузилось | Диагностика: дубликаты имён, пропущенные файлы |

### Во время работы (в основном — агент сам, по правилам `WORKFLOW.md`)

| Команда / скилл | Когда | Что даёт |
|---|---|---|
| `/ticket <текст>`* | Заметил пробел, не хочешь отвлекаться | Issue с меткой и критерием → Backlog; текущая задача не прерывается |
| `/codex:review` | PR открыт | Независимое ревью кода; раунды по риску (`REVIEW_CHECKLIST.md`) |
| `blender-mcp`, `3dsmax-mcp-dev`, `revit-mcp`, … | Перед любым вызовом DCC | Процедура работы со сценой; хук напомнит, если забыто |
| `analyze-architectural-source` | Пришёл новый исходник | Инвентаризация до любой обработки |
| `validate-delivery` | Перед словом «готово» | Финальная проверка поставки |
| `/context` | Хочешь увидеть заполнение | Процент контекста; хук сам предупредит на ~45 % |

### Конец сессии / ротация контекста

| Команда | Когда | Что даёт |
|---|---|---|
| `/handover`* | Контекст ~45 %, PR готов, или уходишь | Коммит; PR, если граница задачи; `HANDOFF.md`; `STATE.md`; карточка → Review. Ответ: «можно /clear» |
| `/clear` | Сразу после `/handover` | Чистый контекст в том же чате и worktree; хук подаёт HANDOFF в новую сессию |
| `/compact` | Не хочешь `/clear`, но тяжело | Сжатие истории. Хуже, чем handover + clear: решения могут потеряться |

### Проверка поведения агента (evals)

| Команда | Когда | Что даёт |
|---|---|---|
| `uv run dt evals --suite regression` | Перед мержем ветки | Грейдеры по транскриптам ветки (`logs/transcripts/`): например, ни одного отказа хука. Отчёт `logs/evals/runs/<время>-.../report.json`; код 0 — всё прошло, 1 — грейдер упал, 2 — нет улик |
| `uv run dt evals --task <id> --evidence transcript=<файл>` | Проверить одну сессию | То же по одному транскрипту |
| `uv run dt evals --suite regression --references` | Изменили грейдер | Грейдеры против эталонных фикстур с известным вердиктом |

### Раз в неделю

| Команда | Что даёт |
|---|---|
| `/reuse-scan`* | По файлам репо за 7 дней (`cases.md`, `logs/agent-usage.jsonl`, `jobs/*/scripts/`, закрытые тикеты): повторы → кандидаты в тул / скилл / паттерн; что не вызывалось; что ждёт тебя. Создаёт тикеты только по твоему «да». Запускать в любом чате на `main`, worktree не нужен |

## Что агент спрашивает, а что решает сам

- **Спрашивает:** технология модели (врезка? глубина? уровень?), данные объекта (id, отметки, что на высоте X — с картинкой).
- **Решает сам:** реализация — алгоритмы, кэши, структура PR, пороги подсказок, формат отчётов. Пишет в PR: «решено: …, потому что …».
- Три попытки → стоп, вопрос или issue.

## Git — четыре слова

| Слово | Что это | Кто делает |
|---|---|---|
| commit | Сохранённая точка в истории на твоём диске. Сколько угодно | агент |
| push | Копирование коммитов ветки на GitHub. Ветка становится видимой для PR | агент, с разрешения |
| pull request | Предложение «принять ветку в main»: описание, ревью Codex, точка отката | агент открывает |
| merge | Ветка вливается в `main`. Момент «принято» | **только по твоей команде** |

Worktree = папка на диске с выписанной веткой. Галочка worktree в приложении создаёт и папку,
и ветку. Ветка со случайным именем переименовывается по `NAMING.md` до первого коммита
(`harness/<что>`, `job/<object-id>-<stage>`, `docs/<что>`).

Продолжить незаконченную ветку: тот же чат, `/clear`, `/takeover`. Не новый worktree.
Новый worktree «от ветки» — только чтобы строить поверх несмёрженного.

## Где что лежит (для `/takeover` и для себя)

| Нужно | Файл |
|---|---|
| Где мы, что в работе, следующий шаг | `docs/HANDOFF.md`, `docs/PROJECT_STATE.md` |
| Незакрытое с номерами | `docs/backlog.md`, доска |
| Правила моделирования | `docs/domain/patterns/`, `docs/domain/conflicts.md` |
| Принятые кейсы и уроки | `docs/cases.md` |
| Имена веток, скриптов, тегов | `docs/agents/NAMING.md` |
| Ревью: раунды, P1/P2 | `docs/agents/REVIEW_CHECKLIST.md` |
| Инструменты и их статус | `docs/agents/CAPABILITIES.md` |
