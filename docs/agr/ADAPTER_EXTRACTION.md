# Connect-квады: выделение операции

Prototype из рабочего сценария Обр22. Ядро: `src/dt_ai/geometry/connect.py`;
старый вход `tools/quad_connect.py:subdivide(..., max_side=3.9)` сохранён обёрткой.
Новый API требует явного параметра, 3.9 м не является нормой следующего объекта:

```python
from dt_ai.geometry.connect import connect_quads
vertices_out, faces_out, parents = connect_quads(vertices_m, quad_indices, max_side_m=3.9)
finish_ids_out = [finish_ids_before[i] for i in parents]
```

NumPy доступен через extras `dev` или `contour-model`. Вход: конечные координаты
N×3 в метрах, целочисленные M×4 индексы, положительная конечная длина.
Выход: вершины, квады и индекс исходной грани для каждого нового квада.
Вызывающая сторона переносит ID и ручные решения через parents; ID0 остаётся ID0.
Функция работает в памяти, не изменяет входы, файлы, UV или статусы приёмки.

Алгоритм сохранён: деления по длине, согласование противоположных/общих рёбер,
билинейная интерполяция, объединение координат с округлением до 8 знаков.
Требуются подготовленные выпуклые невырожденные квады и согласованная сетка.
Полная проверка этих предусловий не реализована. Координатное объединение может
соединить независимые совпадающие поверхности или схлопнуть очень мелкие детали.
Не использовать для произвольного Revit-mesh; ошибка отсутствует не значит QA пройден.
Политика weld оставлена для воспроизведения Обр22, а не объявлена универсальной.

## Проверки

- `python -m pytest -q tests/test_connect_adapter.py`: входы, длины, parents,
  ID0, общие рёбра, отсутствие T-стыков в синтетическом примере, winding.
- Совместимость на локальных входах Обр22 проверяется относительно старого
  `tools/quad_connect.py` из базы `c684d65`; это один проект, не второй кейс.
- Изолированный синтетический Blender readback (новый пустой каталог результата):

```powershell
& '<blender.exe>' --background --factory-startup --disable-autoexec --python-exit-code 1 --python tests/dcc/connect_readback.py -- tmp/connect-readback
```

Сценарий создаёт явно синтетическую сетку, сохраняет и повторно открывает `.blend`,
проверяет координаты, квады, parents, finish_id и отсутствие исправлений mesh.validate.
JSON-отчёт относится только к этому примеру; delivery_passed=false.
Общий `dt build --job jobs/SYNTH-001/project.json --blender <blender.exe>` проверяет
отдельный синтетический FBX-конвейер; сам по себе не тестирует Connect.
