# Компактный отчёт операции

Контракт: `src/dt_ai/core/adapter_report.py`; схема: `schemas/AdapterReport.schema.json`.
Проверка и короткий вывод:

```powershell
.venv/Scripts/python.exe tools/adapter_report.py jobs/OBR22-K02/outputs/adapter-connect/report.json
```

Полный отчёт содержит operation/tool_version/scope, execution, ссылки на входной
и выходной манифесты, проверки с evidence, ручные решения и ограничения.
Манифесты должны хранить пути, параметры, версии и хеши; большие массивы отдельно.
`summary()` возвращает число проблем и первые5 ID без содержимого геометрии/логов.
Ссылки на evidence — указатели, их существование/содержание проверяет исполнитель;
сама валидация JSON не выполняет QA сцены и не удостоверяет истинность отчёта.

`execution=completed` означает только выполнение операции. `required_checks_passed`
вычисляется: выполнение завершено, есть обязательные проверки, все они pass,
нет ожидающих решений. `not_run`, `review`, `fail` не становятся pass.
Успех относится только к объявленной области; `delivery_passed` всегда false.
Принятие пользователем хранится отдельно в реестре опыта/approved-манифесте.

Этот пакет добавляет контракт и reader; подключение Connect/Exterior/Shell остаётся
отдельной задачей. Существующие DCC-скрипты ещё не переведены на него:
их отчёты сохраняются в прежнем формате. Пример пути выше относится к будущему
отчёту Connect и не поставляется в Git.

Код выхода reader 0 означает корректный формат отчёта, включая отчёт о неуспешной
операции; результат операции читать в summary. При ошибке чтения/JSON/контракта
код выхода 1, в stderr — краткая JSON-диагностика без входных данных и traceback.
