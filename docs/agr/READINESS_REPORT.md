подходящими для НПМ без преобразования alpha/normal/упаковки и правил стекла.

## 3. Противоречия и ограничения нормативной базы

[ADR-0002](../decisions/ADR-0002-source-discrepancies.md) содержит теперь 13 записей.
Ни один из перечисленных конфликтов не разрешён молчаливой правкой YAML.

- GeoJSON: обязательность всех полей ОКС, кроме other, на PDF27 против допуска
  отсутствия FNO_code/act_AGR на PDF53–54. Нужен согласованный режим review.
- UCX: 15000 при <50000, иначе5% с округлением вверх, и отдельное упоминание
  100000 на PDF36–37. «Более строгое» из YAML не утверждено заказчиком.
- Зазор UCX0.02–1см на PDF36 — рекомендация; не делать обязательным минимумом.
- МБ/ГБ на PDF6/9/26: десятичная/двоичная граница не установлена.
- Плотность НПМ на PDF10: единицы текста не соответствуют численному примеру.
- Заглушки НПМ128², M_Glass_01..07 и условная opacity растений не полностью
  отражены YAML (PDF3–4, 9–10, 13).
- Граница100 UDIM-карт/плиток и слоты на PDF30 требует согласованной трактовки;
  поворот UV лишь не рекомендуется, зеркальность запрещена (PDF31).
- На PDF39 в рисунке повторён1078 вместо1079. В коде используется последовательная
  сетка по тексту. На PDF32 визуально подтверждён знак деления Lт÷Lп.
- Новая находка аудита: PDF40 рис.2.1 пишет800000 для ОКС и3000000 для Ground;
  таблица PDF28–29 задаёт1000000 и ступенчатые лимиты площади до4500000.
  Предложен приоритет таблицы, но для спорных случаев до решения нужен review.
- Профили неполны: свет, alpha-плоскости, индекс Address, ограничения GeoJSON
  и прочие исключения требуют расширения с трассировкой (PDF26, 36–38, 53–55).

232 строки `traceability.json` обеспечивают ссылки **имеющихся полей профилей**.
Это не доказательство полноты всех требований PDF и не232 выполненные проверки.

## 6. Готовность приложений и адаптеров

- **Blender4.4.0:** работающий `adapters/blender/bridge.py`, операции export/audit,
  фактический round-trip этого аудита. Только background/factory-startup и fixture
  layout. SINTEZ/BMAX в этих процессах не запускались. Production adapter — prototype.
- **3ds Max2024:** в предыдущем этапе успешно читались capabilities, UI/пути/FBX
  настройки через существующий bridge; это сохранено в `inventory/max-runtime.json`.
  В Digital Twin исполняемого Max export/audit нет, только README-контракт.
  Было две сессии: до изменения сцены требуется явная привязка к PID/документу.
  Max2026 обнаружен по установке; практической проверки нет. Версия2025 из
  брифа не подтверждается данной инвентаризацией.
- **AutoCAD2025:** COM-код CAD-01/02 существует, но этот проект не проверял
  документ/объекты через COM и не выполнял DWG→Placement. Старый GP-процесс
  подтверждает существование подхода, не координаты нового ОКС.
- **Revit2025.2:** addin-манифесты и код двух bridges есть; handshake/документ

## 8. Что нельзя проверить без реального ОКС

Необходим не произвольный найденный проект, а выбранный и разрешённый комплект:

1. FBX или утверждённый master, единицы/версия экспорта, исходный RVT/SketchUp при
   использовании этого пути. Нужны разрешения хранения и копия для испытаний.
2. Альбом фасадов/материалов/окон с размерами и согласованная карта назначений.
   Без него не доказать цвет, фактуру, членение, этажность, крышу и первый этаж.
3. DWG/СПОЗУ, система координат/UCS/единицы, точка вставки, проектная отметка0.
   Без них не проверить V013/014/017 и плановый допуск0.5м.
4. Эталон принимаемого НПМ/ВПМ-пакета, GeoJSON и отдельное ТЗ/договорные исключения.
   Без них остаются открытыми спорные нормы, адреса и обязательность данных.
5. Ответственный за материалы, геометрию, placement, UCX и финальную выдачу.
   Без подписанного решения нельзя закрыть V015/016/017.

Пустоты арок/дворов, покрытие UCX и художественную пригодность можно сначала
тестировать синтетически, но соответствие конкретному зданию — только на его
исходниках. Время/стоимость ручного процесса, ускорение, масштабируемость на больших
моделях и процент автоматизации пока не измерены. Синтетический куб этого не доказывает.

## 9. Решение о продолжении и условия повышения уровня

### Готов к разработке независимого ядра: **ДА**

Практическое основание: 33 теста текущего коммита; отрицательные форматы/каналы/UV/
ZIP проверены; merge не стирает approved; индексатор работает на оригинале;
сборка даёт два реальных FBX с проверкой байтов после ZIP. Контракты, source lock,
трассировка и рабочий CLI позволяют развивать код с регрессионным контролем.

«Да» относится к **разработке**, а не завершённости ядра/нормативного валидатора.
Следующая задача — INT-001 для DT-020/021: карта native findings SINTEZ→V-code→PDF,
разделение check/fix/import, изолированный synthetic harness. Затем нормативные
ZIP/GeoJSON contracts и fixtures. Не создавать ещё один полный checker без анализа
имеющегося. Новые спорные правила остаются review; Context7 починить до работы,
требующей этого канала документации. Эти ограничения не отменяют проверенную
возможность развивать независимый код на имеющихся документах.

### Готов к общей интеграции с DCC: **НЕТ**

Есть практическое **ДА только для Blender4.4.0 и synthetic export/audit**.
Общий уровень охватывает заявленный рабочий цикл, а не факт наличия одного bridge.
Для Max нет DT export/audit runner; CAD/Revit runtime не проверены; SINTEZ/BMAX/
RizomUV ещё не выполнены как изолированные DT-задачи. Нет общей проверенной схемы
timeouts, идентичности документа, версий tool/plugin и сохранения оригинальных UV.

Условия перехода: один утверждённый transport на приложение; закреплённые версии;
fixture→экспорт→повторный импорт с units/UV/material/embedding и failure tests;
для CAD — контроль DWG→Placement; для Revit — документ/единицы/IDs/контуры.
Начинать эти ограниченные интеграционные эксперименты можно сейчас, объявлять
готовой межпрограммную цепочку до их завершения нельзя. Revit не обязан блокировать
первый FBX-пилот: backend пилота надо явно выбрать и проверить.

### Готов к пилоту на реальном ОКС: **НЕТ**

Конкретное основание отказа: `synthetic=false` отклоняется сборщиком; отсутствуют
нормативный publisher, GeoJSON, Ground/UCX/glass и процедура визуального утверждения;
V001–V014 не выполняются, V015–V017 не подписаны. Нет выбранного комплекта исходников
и подтверждённых координат/материалов; `passed=false` корректен.

Условия перехода: получить комплект из раздела8; выбрать основной FBX/DCC-путь;
подключить готовый вручную approved body; реализовать DT-020–023 и только необходимые
для этого объекта ветки стекла/Ground/UCX/света; провести полный запуск, readback,
overlay и утверждение результата. DT-030–032 и полная автоматическая реконструкция
произвольного здания не обязательны для первого пилота по брифу.
