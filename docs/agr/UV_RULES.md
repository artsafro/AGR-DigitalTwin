# UV: повторное использование текстур НПМ и ВПМ

Источник: прямое уточнение пользователя 27.09.2026 после просмотра v010.
Статус: принятое правило работы проекта. Это не новая норма исходного PDF.

## Приоритетное уточнение после приёмки ВПМ v011

Пользователь принял ВПМ v011. Для НПМ **ОКС/архитектуры нет требования к texel
density Ground**: не подгонять размер материала под диапазон плотности рельефа.
Подтверждено визуально в исходном PDF, страница10, раздел6, пункты1–2:
требование относится к поверхности рельефа, ОКС включён в исключения.
`NPM_STANDARD.yaml` уже отражает это исключение; нормы не изменены.
Обязательный критерий НПМ-ОКС — одинаковый физический/визуальный размер кирпича,
плитки и других элементов отделки при сравнении с утверждённой ВПМ. Размер
изображения элемента в атласе и масштаб его UV менять согласованно. Выбирать
достаточное качество рисунка, соблюдать padding и границы материала. Число px/м
можно измерять для диагностики, но не использовать как ворота соответствия ОКС.
Проверять масштаб по сохранённым файлам и одинаковым камерам; совпадение размера
не означает одинаковой резкости карт разного разрешения. Принятую ВПМ сохранять.

## Раскладка

- Сначала группировать грани по отделке/текстурному ID, затем раскладывать UV.
  Не выделять уникальную площадь текстуры каждому повторяющемуся полигону.
- Одинаковые и близкие по размеру участки одного материала складывать UV друг
  на друга в общей области. Сохранять физический масштаб, пропорции, направление
  рисунка и фазу швов; близкие размеры не означают разрешения растянуть остров.
- НПМ: один атлас с областями по типам текстур. Например, три типа плитки —
  три области, которые повторно используют соответствующие UV-полигоны.
- ВПМ: целевой принцип — один UDIM на текстурный ID/тип отделки, все подходящие
  UV этого материала используют этот тайл с намеренными наложениями.
  Для четырёх текстурных ID цель — четыре UDIM, а не19 из уникальной упаковки.
- Если участок не помещается при требуемой плотности и padding, делить раскладку
  на логичные UV-участки и укладывать их в ту же область/тайл. Не увеличивать
  число UDIM по умолчанию и не уменьшать плотность ради укладки.
  Требование плотности применять только к соответствующему виду модели/геометрии;
  к НПМ-ОКС оно не относится.
- UV-шов разъединяет существующие грани. Разделение внутри одной большой грани
  требует согласованных quad-разрезов по правилам геометрии; не выдавать его за
  операцию только над UV. Сохранять форму, проёмы и инстансы; без T-стыков.
- При наложении должны совпадать используемые текстуры и их назначение.
  Не смешивать разные отделки, не зеркалить рисунок и не накладывать уникальные
  надписи/локальные детали на повторяемые области.
- Текстурный ID — смысловая группа отделки, не обязательный отдельный shader slot.
  Сохранять явное соответствие `finish_id → atlas_region/UDIM`; неизвестный ID0
  не присваивать произвольной отделке. Стекло учитывать по отдельному профилю.

## Проверки и применение

Намеренные UV-overlaps разрешены внутри объявленных групп повторения. Ошибками
остаются наложения несовместимых материалов, зеркальность, выход за свою область,
неверный масштаб и нарушение padding. Запрет геометрических overlaps не меняется.
При повторном чтении проверять mapping, плотность, направление/фазу рисунка,
границы областей, фактическое число UDIM и неизменность принятой геометрии.

Нормативные YAML не изменены. `VPM_STANDARD.yaml` уже допускает повторяющиеся
острова с наложением; секция uv ссылается на PDF31/32/39. Правило «один текстурный
ID — один UDIM» здесь является рабочим указанием пользователя, а не цитатой PDF.

v010 принят пользователем по общему виду текстур/атласов, но его19UDIM остаются
прежней уникальной упаковкой. Новая схема в сценах и валидаторе ещё не реализована.

компактный атлас/UDIM, проверка сохранённых файлов и вида на модели.
