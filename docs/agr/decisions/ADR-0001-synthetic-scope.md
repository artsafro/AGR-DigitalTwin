# ADR-0001: независимое ядро и границы первого примера

Статус: принято как инженерное решение для версии 0.1.0; не требование заказчика.

Источник постановки: бриф, разделы 2, 4, 8–10. Исходные профили и PDF имеют приоритет.

Python CLI, Pydantic-контракты и Pillow строят два представления одного реестра.
Синтетический master — куб 2×2×2 м с шестью устойчивыми surface ID и двумя
явно вымышленными материалами. Числа задаёт `fixture-definition.json`, а не
измерение реального альбома. Подпись `fixture-author` разрешает только тест.

Blender запускается отдельным процессом с `--factory-startup`. Открытые сцены
пользователя не используются. FBX проверяется повторным импортом в новый процесс
после чтения ZIP. При проверке embedding НПМ рядом с FBX нет исходного PNG.

`development_bundle.zip` — внутренний формат разработки. JSON-снимки, свободные
PNG НПМ и отсутствие Ground/GeoJSON/UCX делают его непригодным для официальной
сдачи. Имя FBX содержит npm/vpm для различения тестов, а не нормативную маску.
Не подменять этот архив нормативным ZIP. Поле `passed` в текущем контракте всегда
false, даже когда технические проверки C001–C004 пройдены.

C001–C004 — инженерные проверки частей требований. V001–V017 остаются явными
not_run/review, пока не реализованы все составляющие проверки на реальном пакете.
Страницы у C-проверок указывают, откуда взяты проверяемые свойства; хеширование,
внутренний JSON и ограничение распакованного dev-пакета в 256 МБ — решения кода.

Выходы воспроизводимы для независимого ядра, включая байты PNG/JSON/ZIP без DCC.
Blender может записывать время/ID в FBX и blend: побайтовую идентичность DCC-файлов
не обещаем. Вместо неё проверяем геометрию и UV при повторном импорте.

Ограничения: нет автоматического восстановления body, окон, стекла, коллизий,
реальной геопривязки, GeoJSON и официального publisher. Частичная пересборка
сохраняет неизменные PNG и сообщает хеши; общий планировщик DAG ещё не реализован.
