# ADR-0003: контракты и устойчивые идентификаторы

Статус: принято для независимого ядра v0.1.0.

Версия контрактов — 1.0.0. Pydantic запрещает неизвестные поля, нечисловые
значения координат, повторные ID, отсутствующие material references и статус
approved без автора/даты/области решения. JSON/YAML с повторными ключами отклоняется.
JSON Schema сохраняются в `schemas/`, `dt schemas --check` обнаруживает дрейф.
Семантические межполевые ограничения требуют Python-моделей и не исчерпываются
JSON Schema. Миграций пока нет: другие schema_version отклоняются.

Surface ID задаётся источником и не зависит от координат, порядка обхода или
цвета материала. Для реальных перестроений понадобится явный old→new mapping;
этот этап не реализован. Material ID — внутреннее имя, slot и tile — отдельные поля.
Сортировка material IDs даёт стабильную раскладку при изменении цвета. Добавление
нового ID может изменить раскладку, что фиксируется изменением layout.json.

`registry merge` сохраняет утверждённую запись, а несовпадающее новое предложение
пишет в отдельный conflicts.json. Наличие предыдущего approved не означает,
что изменённое предложение автоматически утверждено.

Версии профилей и SHA-256 PDF входят в manifest. Исходные файлы задания проверяются
по относительным путям и SHA-256. Изменение входа требует обновления manifest
и повторного решения владельца; автоматически утверждения не продлеваются.

Нормативный отчёт сейчас намеренно не умеет passed=true. Для полноценного
publisher понадобятся обязательные rule IDs, подписи ручных ворот, версии входов
и механизм инвалидации подписей; это отдельное расширение версии схемы.
