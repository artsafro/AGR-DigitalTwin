# Обновлённый план интеграции

26.09.2026. Основание: локальная read-only инвентаризация, [реестр](catalog.json).
Статус: **инженерное предложение на основе фактов; интеграции ещё не реализованы**.
Бриф и исходные стандарты не переписаны. DT-ID и их критерии сохраняются.

## Архитектура после инвентаризации

Сохранить `dt_ai` как независимое ядро источников, ID, утверждённого реестра,
зависимостей, файловых контрактов, профилей и отчётов. Не создавать конкурирующие
вторые геометрические библиотеки, UI меню Max или новый DCC bridge.

Добавить вокруг существующих инструментов тонкие адаптеры:

- **Max2024:** действующий Codex MCP/native bridge. На входе pinned session/PID,
  версия Max и source scene identity. Сначала inspect/dry-run. Изменения — только
  отдельная копия/тестовая сцена и явно выделенная output-папка. Инвентаризация
  показала два процесса и два checkout MCP; выбор сессии обязателен.
- **Blender4.4:** текущий `adapters/blender/bridge.py` остаётся транспортом фонового
  экспорта/readback. Для SINTEZ и CheckToolBox — отдельные workers с проверенным
  набором аддонов, версиями и зависимостями. Пользовательские prefs не загружать
  целиком. Для обычного headless export сохранить factory-startup/disable-autoexec.
- **GeoAGR:** основной UI пока требует контрольного запуска в отдельной сцене.
  По запросу пользователя исследована поставка13.63: обнаружены API трёх DLL,
  отдельно проверены CLI `ucx_check`/`uvdilate` на синтетических файлах.
  См. [GEOAGR_13_63_REVIEW.md](GEOAGR_13_63_REVIEW.md). Извлечение metadata
  не означает готовности DLL-адаптера; основной AutoIt SCRIPT не декомпилирован.
  Не автоматизировать клики вслепую и не использовать clipboard execute как API.
- **AutoCAD2025:** переиспользовать pywin32/GetActiveObject и проверенные функции
  `autocad-mcp`; разнести чистое чтение сущностей и изменяющий HATCH/Wblock.
  Контуры нормализовать в manifest с units, WCS/UCS, elevation, bulges, handles.
- **Revit2025:** выбрать named-pipe RevitBridge как первый кандидат; handshake
  с проверкой source DLL/version. ContourProbe интегрировать отдельно, сохранив
  host/link transforms, ElementId/UniqueId, уровни и границы области выгрузки.
  Совпадение source-кода и установленной сборки сначала проверить, не предполагать.

Будущий adapter result должен содержать `tool_id`, `tool_version`, `source_hash`,
`host_version`, `operation`, `input_hashes`, `output_manifest`, `findings`,
`side_effects`, `status` и признак `read_only`. Native finding сохраняет свой ID,
объект/файл/пиксель/грань, actual/expected и измерение. Отдельное сопоставление
`native_rule_id → DT V-code → PDF page → interpretation` выполняет ядро.
Эти поля — проект будущего контракта, не уже реализованная схема.

Чужой `OK` не преобразуется автоматически в `delivery passed=true`.
Несопоставленные проверки, противоречия и ручные ворота остаются review/not_run.
Карта сравнения и версии внешнего инструмента фиксируются вместе с результатом.

## Порядок работ

### INT-001 — совместимость существующего валидатора (следующая задача)

Относится к DT-020/021. Зафиксировать hash SINTEZ1.6.1, Blender4.4 и wheels.
Статически отделить чистые проверки от импорта, исправлений, распаковки/перезаписи
и updater. Составить полную матрицу существующих rule IDs к PDF/нашим V001–V017.
Спорный UCX15k/5%/100k вынести в открытое решение, не наследовать молча.

Затем на **копиях синтетических файлов** в изолированной output-папке проверить
верный/повреждённый ZIP, лишний файл, PNG mode/size, swapped ERM, normal sign,
UDIM1001/1010/1011/1100 и выход за профиль, недостающий tile, material slots,
FBX header, GeoJSON fields. Упрощённый текущий development ZIP не называть
нормативной положительной фикстурой: сначала подготовить согласованный полный
контрольный пакет. Неподтверждённые поля — отдельные negative/review fixtures.

Готовность: сохраняются native findings и source evidence; покрытие таблицы
полно; на каждой спорной норме видно расхождение. Нет записи в исходные ZIP,
установку аддона и открытые пользовательские сцены. Реализовать только пробелы
DT-020/021, для остальных оставить внешнюю реализацию и независимые контрольные
тесты. Это заменяет прежний план «сразу писать весь инспектор заново».

### INT-002 — транспорт и явные профили экспорта Max/Blender

DT-012/013/021/022. Не писать BMAX заново: обернуть его либо штатный FBX API,
сравнив минимальные операции на тестовой сцене. BMAX2012 и общий embed=false
не годятся как preset официального НПМ. Ввести отдельные npm/vpm preset snapshots,
восстановление runtime-параметров, job-specific temp и стабильные source IDs.
Тест: units/axis/pivot/XYZ, раздельные material ID/slot/UDIM, UV seams, NPM embedded
PNG без файла рядом; ВПМ без внешних путей; повторный импорт actual ZIP.

Готовность: файлы дают одинаковую семантику через Max и Blender; нет reliance на
неявный UI preset. Установленный FBX transport остаётся, ядро сравнивает outputs.

### INT-003 — реестр → существующие атласы → НПМ/ВПМ

DT-010–014. Приоритет — `.window_facades` seam-aware UV и уже работающий
`facade-atlas` UI/layout. Ввести MaterialRegistry/Surface ID/source region,
профиль resolution/padding и детерминированный output. Выбрать с пользователем
canonical Atlas_Builder24/portable вместо поддержки трёх равнозначных форков.
Сохранить GUI как инструмент выбора, а approve/conflict оставить в ядре.

Для ВПМ можно повторно использовать подход SINTEZ `build_udim_material`: Non-Color
для ERM/Normal, разбор R/G/B, инверсия зелёного только в Blender-preview узлах
DirectX→OpenGL. Файлы normal остаются DirectX. Это закрывает известный пробел
текущего synthetic .blend, где карты пока не подключены. Пиксельный тест обязателен
для OpenCV RGB/BGR. Roughness/metalness по яркости и белые окна как glass остаются
предложением для просмотра, пока материал не утверждён человеком.

Готовность: approved не затирается; меняются только зависимые outputs; геометрия/UV
соседних поверхностей сохраняется. Не добавлять ещё один atlas GUI.

### INT-004 — позиции и DWG extraction

DT-023. Взять `agr.hosts.autocad.inspect_active_drawing`/COM extraction как основу.
На копии DWG проверить полилинии и штриховки с дугами/отверстиями/разными elevation,
UCS≠WCS, вложенными блоками и единицами. Сохранить raw coordinates и transform,
не приводить всё молча к нулю. Для loop nesting не использовать только largest loop.
Реальный перевод в МСК-77 и нулевая отметка требуют исходных координат/СПОЗУ.
Числа из AutoLISP NUM2CIRCLE не считать высотами без источника.

Готовность: контрольные координаты/высоты/orientation совпадают с источником;
GeoAGR/Andrew importer используется как дополнительный readback после проверки.

### INT-005 — геометрия/окна из существующих исследований

DT-030/031/032. Переиспользовать ContourProbe + contour_core и FBX facade scanner.
Сначала одна стена с окнами, затем согласованный участок двух этажей. Сохранить
раздельные внешние loops, исключённые кривые, source IDs, link transforms и
фактические offsets относительно levels. Не превращать Exterior wall side в
доказательство видимости всей наружной оболочки.

Перенести WindowHelpers/Dummy placer и DOCX-atlas в адаптер WindowType только
после проверки единиц, размеров и соответствия вставок. Не переносить <100мм
из старого эксперимента как общий строительный допуск. Полное тело здания не
объявлять восстановленным по одному успешному фасадному patch.

### INT-006 — UCX из уже имеющихся алгоритмов

DT-033/021. Сравнить Andrew UCX_Tools/Check, GeoAGR, старый grid splitter и свежий
Blender ucx_test. Приоритет переиспользования — чистые функции проверки/подрезки,
компонентные IDs, convex/closure/gap и coverage audit из ucx_test. Извлечь kernel,
не переносить сценовые адреса, список проблемных пар и подобранные допуски.

Тестовая модель должна содержать арку, двор, тонкий выступ, несколько disconnected
компонентов и большие координаты. Проверить проходы и оболочку после экспорта.
Число полигонов не увеличивать лишь ради прохождения процентного UCX-лимита;
коллизия должна быть оправдана геометрией и согласованной трактовкой PDF.

### DT-022 и реальный пилот

Собрать publisher из проверенных adapters и ядра; итоговый actual ZIP снова
проверять независимым readback. Новый код писать только для недостающих контрактов,
сопоставления правил, детерминизма, packaging и доказательств.
INT-005/006 не задерживают первый пилот с готовым утверждённым body и UCX.
Входы пилота остаются прежними: разрешённая модель, альбом фасадов, DWG/СПОЗУ,
координаты/нулевая отметка, пример принимаемого пакета/GeoJSON, отдельное ТЗ.
