## Полезная логика и ограничения

### GeoAGR — уточнение MAX-01

Результат всего 406 байт: загрузчик запускает `GeoAGR.exe` с путём INI, затем
выполняет текст из буфера обмена. Алгоритмы атласа/UCX/GeoJSON в этом MSE отсутствуют.
INI с лицензионными данными в этом исследовании не читался. Запуск EXE и получение
его содержимого через буфер обмена не выполнялись. Основная реализация остаётся
неисследованной; декодирование загрузчика не открыло весь GeoAGR.

Для адаптера нужен поддерживаемый контракт результата. Существующую связку
EXE → глобальный clipboard → execute нельзя принять за детерминированный API.
Решение MAX-01 остаётся: изучить на изолированной тестовой сцене.

### RizomUV Bridge — MAX-06, INT-002/003, DT-012/013

Восстановлены UI версии **1.5.1** по changelog и модуль функций.
Есть готовая цепочка копий объектов → FBX → Lua/RizomUV → импорт → перенос
map channels на исходные узлы через ChannelInfo. Узлы связываются через handle,
вписанный в имя экспортируемого объекта. Основные точки: `RUVB_ExportObjs`,
`RUVB_Export_FBX`, `RUVB_Import_FBX`, `RUVB_GetResult`.

Условия перед переиспользованием:

- UI в режиме New очищает каналы 2+ у выбранных объектов до экспорта; также
  вызывается cleanup геометрии. Обрабатывать копии, сохранять исходные UV.
- Export: ASCII, Y-up, EmbedTextures=false, Triangulate=false, версия FBX из INI;
  параметры единиц/масштаба экспорта закомментированы. Push/Pop настроек тоже
  закомментированы. Это транспортный профиль, не профиль нормативной выдачи.
- Импорт: ScaleConversion=false и ScaleFactor=1; UV переносятся без видимого
  сравнения топологии. Нужна проверка количества/порядка faces/map vertices.
- Разбор handle из имени использует execute. Адаптер должен принимать только
  числовой ID и проверенный manifest, сохраняемый между процессами.
- Ожидание результата основано на одинаковом размере FBX через 0.1 секунды;
  это не надёжное подтверждение завершения. Нужны timeout, атомарная готовность,
  отдельная job-папка и привязка к запущенному процессу.

Решение: доработать транспорт и обернуть адаптером после теста seam/tile/ID
round-trip. Не переносить старые допущения о порядке вершин в независимое ядро.

### UV startup — уточнение MAX-07

- `UVTools_loader`: настоящий код находится в `NikScripts/UVTools/UVTools.mse`,
  плюс DLX по версии Max и LoadIcons.dll. Загрузчик удаляет старые DLX,
  правит Plugin.UserSettings.ini и загружает плагины. Для read-only анализа
  его нельзя запускать; основной UVTools в этом этапе не раскрывался.
- `polyunwrapper_autoload`: передаёт управление DLL и utility MSE. Раскрытие
  загрузчика не даёт реализации развёртки.
- `auvn_autoload`: формирует путь к auvn.mse, но try-блок пустой. Именно этот
  файл основной скрипт не запускает. Возможен другой путь запуска через UI;
  утверждать полное отключение Advanced UV Normalizer нельзя.

### Decal Projector 0.87o — комплектный пример, MAX-27

Внутренняя атрибуция OYH, 2011; не найдено подтверждение установки/использования.
Полезны для DT-012/013: разделение mesh vertices по UV-швам
(`SplitVertsByMapVerts`, строки 1912–1979), получение UV по мировой точке/лучу,
рекурсивный обход материалов и карт, композиция и запекание decal.
Это не готовый НПМ-атлас или генератор нормативных ERM/Normal.

`bakeToTex` (с 2144) работает со сценой: удаляет dpObject_*, предлагает удалить
все источники света, преобразует объекты и создаёт вспомогательную геометрию.
Изучать на тестовой сцене; при переносе алгоритма выделять чистую обработку данных.
Лицензия инструмента-декодера не определяет право переноса данного примера.
