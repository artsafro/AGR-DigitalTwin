## Уже включено в 0.5

- **UV одной отделки → UDIM**: идея из Maf Tools, новая реализация в extensions.ms.
  Пользователь явно задаёт Material ID и тайл. Сохраняется масштаб, соседние ID
  не сдвигаются, общие map-вершины отделяются. Область больше тайла отклоняется.
  Это перенос, не автоматическая упаковка и не определение отделки по номеру.
- **Выпуклая оболочка**: подход UCX_Tools/nvpx, новая реализация на копии выбранных
  полигонов. Исходник не конвертируется и не меняется. Плоские входы отклоняются
  до nvpx: тест показал, что сам nvpx способен придать плоскости толщину.
  Нет декомпозиции, проверки зазоров или автоматического обхода проёмов.
- **Файлы текстур и потерянные ссылки**: доступ к существующему обходу материалов
  через отдельную понятную панель. Никакой перепривязки или замены материалов.
  UDIM-токены, последовательности и закрытые плагины требуют отдельной поддержки.

## Следующие переносы по исходным большим инструментам

1. **Facade Atlas**: камеры → физические размеры фасадов → изображения → атлас
   → UV → материал → экспорт. Кандидат на законченный сценарий для НПМ.
   Нужны явная привязка фасад–изображение и проверка масштаба после сохранения.
2. **FloraAtlas**: сбор карт, alpha/mask, упаковка, материал, UV. Прочитана структура
   функций, но не проверен весь алгоритм. Автоуменьшение при упаковке нельзя
   переносить без отображения полученной детализации и сравнения внешнего вида.
3. **FreeSpot_Tools**: предварительный список близких источников и сокращённая
   отдельная версия света. Расстояние само по себе не доказывает одинаковый свет:
   учитывать направление, тип, цвет, мощность; итог проверять рендером.
4. **pipe_optimize_clone.ms**: отдельная версия труб + ProOptimizer с KeepUV,
   LockMat и защитой границ. Не применять ко всему BODY: возможна триангуляция.
   До включения нужны сравнение силуэта, границ и UV на нескольких типах труб.
5. **opening_grid_cleaner**: удаление лишних рядов вокруг проёмов. Полезнее простого
   Remove, который может дать n-gon. Нужны тесты углов, Т-стыков, соседних проёмов.
6. **Ground**: извлекать обработку контуров и покрытий отдельно. Найденная веерная
   триангуляция не подходит как универсальная квадовая сетка проекта.
7. **UCX_Tools**: сечения/декомпозиция и компонентная проверка пересечений.
   Нельзя считать bounding box готовой коллизией здания. Сначала диагностировать,
   затем показывать предлагаемые изменения с проверкой проёмов.
8. **PolyActions / Maf / GeoJSON**: переносить по операции с явными входами,
   а не запуском rollout. GeoJSON требует подтверждённой координатной схемы;
   номера Material ID нельзя автоматически превращать в семантику отделок.

## Случайная разведка и идеи

Воспроизводимая выборка: seed20260927, 12 новых кандидатов вне Program Files.
Она не является Monte Carlo-оптимизацией и не оценивает качество статистически.
Из выборки подробно прочитаны три особенно релевантных файла:

- `.window_facades/verify_uv_signs.py`: сравнивает отношения UV/мировых длин рёбер,
  проверяет фактический атлас2048 и создаёт контрольный рендер. Хороший кандидат
  для панели «Где растянулась текстура». Сейчас жёстко зашиты объект,62полигона,
  5материалов и пути; скрипт меняет render-сцену — напрямую запускать нельзя.
- `.window_facades/analyze_facade_islands.py`: группирует связные грани одного
  Facade_ID и выводит размеры. Кандидат: «Найти потерянные/разорванные участки
  фасада», выделение проблем в Max. Сейчас зависит от Blender и Object2389.
- `zavod/projects/facade-atlas/facade_atlas/alignment.py`: выравнивает обрезки
  фасадов по общей линии земли листа. Кандидат: мастер изображений атласа
  с визуальным подтверждением земли, особенно для корпусов разной высоты.

Остальные9 записей выборки пока только проиндексированы. Полная выборка в JSON.

Дополнительные идеи для единого интерфейса:

- По уточнению пользователя отдельный инструмент сравнения ВПМ/НПМ исключён
  из плана. Правила сохранения физического размера рисунка остаются в силе.
- **Комплект текстур**: план копирования, конфликты одинаковых имён, новый каталог,
  manifest и повторное чтение; только затем версия с перепривязкой материалов.
- **Объяснить проблему**: строка диагностики → выделить проблемный объект/грани
  → показать причину → предложить конкретную исправляющую операцию.
- **Маршрут по типу объекта**: здание/стекло/Ground/Flora/UCX/свет. Показывать
  подходящие инструменты, сохраняя доступ к полному списку без скрытых наборов.

Приоритет уточняется через целевой пайплайн ниже, затем Flora и
свет, затем геометрические очистки. Количество кнопок само по себе не сокращает
работу; для каждой операции нужны результат, отмена и понятная проверка.

## Уточнение пайплайна после версии 0.5

Пользователь исключил сравнение НПМ/ВПМ и временно запретил Computer Use и Max.
Этот разбор выполнен только по файлам. Ни UI, ни сцена, ни исполняемые скрипты
не изменялись. Ниже — проект следующего этапа, а не уже реализованные функции
и не дополнительные требования заказчика.

Сейчас Workbench обеспечивает отдельные операции над текущим выделением.
Есть начало подготовки UV, простые геометрические команды, имена, частичная
диагностика и экспорт отдельного FBX. Сквозной процесс пока не собран:
между UV и экспортом отсутствуют оформление материалов/карт, а между экспортом
и передачей — сборка комплекта. Создание UCX не включает связь с владельцем,
декомпозицию и проверку пригодности. Свет — размещение, а не полный выпуск света.

### Общая структура двух вкладок

Внутри НПМ и ВПМ сгруппировать инструменты по результату работы:
«Модель», «Материалы и UV», специфические разделы профиля, «Проверка и выпуск».
Сохранять прямой доступ к операциям: это ориентир, не обязательный мастер,
который заставляет проходить заново уже готовые этапы. Источник может быть
готовым мешем, частично подготовленной сценой или моделью с готовыми материалами.
Моделирование с нуля по Revit/чертежам — отдельная расширенная ветка.

Роль объекта (здание/стекло/земля/растительность/коллизия/свет) определяет
подходящие действия. Это не возврат сохранённых «наборов»: кнопки по-прежнему
обрабатывают текущее выделение. Перед файловым выпуском нужен явный список
объектов и файлов; область выпуска подтверждается отдельно от выделения
для текущей операции. Финальные имена удобно выдавать после сборки частей.

### НПМ

Подготовить геометрию → оформить материалы/атлас → разместить UV → собрать
части модели → проверить → экспортировать FBX и проверить фактический файл.

Атлас имеет минимум два входа: готовые изображения фасадов или подготовка
изображений из сцены. Если текстуры уже готовы, камеры и запекание пропускаются.
Простая UV-проекция не заменяет раскладку по областям готового атласа.
Ground и Flora — самостоятельные ветки; их инструменты не должны становиться
обязательными шагами для здания. Плотность Ground не применяется к НПМ-ОКС.

Ключевой пробел: единая панель, связывающая поверхность/отделку, изображение,
область атласа, физический масштаб и материал. Далее — управляемое объединение
частей, сохранение Material ID и проверка результата Attach.

### ВПМ

Подготовить геометрию → оформить отделки и UV/UDIM → подготовить карты →
сделать и проверить коллизии → подготовить свет, если он входит в задачу →
собрать FBX, карты и GeoJSON → проверить комплект.

Ключевые пробелы: реестр отделок с понятными названиями и назначенными картами,
явная связь отделки с UV и тайлом, подготовка Diffuse/Normal/ERM по профилю,
связь UCX с моделью, проверки коллизий, отдельный выпуск света при необходимости,
подтверждённая система координат и сборка GeoJSON. Material ID и UDIM — разные
поля, автоматическое равенство между ними недопустимо.

### Порядок следующей разработки

1. Связать текущие команды в понятную навигацию по этапам и роли объекта.
   В каждой панели: что обрабатывается, ожидаемый результат, доступные действия.
   Незавершённые модули вынести из рабочего списка в план разработки.
2. Сделать «Материалы и UV» центральным разделом: показать используемые отделки,
   полигоны, Material ID, карты и UV; выделять нужные поверхности из списка;
   восстанавливать потерянные ссылки с предварительным просмотром совпадений.
   Затем подключать атлас НПМ и оформление UDIM/карт ВПМ.
3. Добавить подготовку и сборку геометрии: целевые очистки, проверку нормалей,
   вырожденных граней, дублей и границ; управляемый Attach без потери материалов.
   Reset XForm, Collapse и Weld не выполнять общей безусловной кнопкой.
4. Сделать выпуск комплекта: список объектов, имена, подтверждённые настройки
   экспорта, новый каталог версии, карты/GeoJSON по профилю, отчёт и readback.
5. Переносить Ground/Flora, оптимизацию труб, свет и сложные UCX как отдельные
   рабочие ветки, каждая со своим результатом и проверками.

Важная связка диагностики: проблема → выделить объект/грани → объяснить причину
→ открыть подходящий инструмент → повторно проверить. Состояние «проверено»
не должно оставаться актуальным после изменения соответствующих данных.
Создание копии остаётся необязательной операцией с явным назначением.
