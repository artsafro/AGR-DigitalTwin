## Вывод

Наиболее полезное ядро уже распределено между тремя группами:

1. `zavod/scripts` и `projects/facade-atlas`: подготовка исходников, фасадные камеры,
   атлас, организация сцены, облегчение деталей и FBX.
2. `Плагины 3dMax/Andrew_scripts`: UDIM, плотность, запекание, рельеф,

3. `A101AGRLP.ms`: образец организации подготовки ОКС/Ground/Flora,
   материалов, имён и экспорта для НПМ; правила следует актуализировать.

Предложение: новое общее окно с ровно двумя основными вкладками **НПМ** и **ВПМ**.
Над вкладками — проект, область обработки и папка результата; под ними — журнал.
Одинаковые операции вызывают общие функции с профилем вкладки. Сами рабочие
исходники остаются отдельными версиями, чтобы обновление одного модуля не ломало остальные.

Дополнительно: все 11 скриптов из `Для Артема.zip` побайтово совпали с
одноимёнными файлами `Andrew_scripts`. Это резервная копия набора, а не
отдельная ветка для интеграции. Две копии H_instancer тоже совпадают по SHA256.

## Вкладка НПМ

### 1. Подготовка

- «Анализ сцены»: `scene/agr_inspect_max.ms`, `scene/scene_load_report.ms`.
- «Разобрать FBX»: `fbx/inspect_fbx.py` и `fbx/zavod_fbx_tool.ms`.
- «Слои по именам»: `layers/names_and_layers.ms`.
- «Найти мелкие детали»: `layers/analyze_layers_for_optimize.ms`, затем
  отдельно узкий `move_fasteners_to_optimize.ms` или широкий `move_guess_optimize.ms`.
- «Объединить по материалу»: `mesh/attach_by_material_mesh.ms`.

Область должна задаваться явно: выделение / выбранный слой / набор объектов
проекта. Операции, которые сейчас обходят всю сцену, адаптировать под эту область.

### 2. Облегчение геометрии

- `pipes/pipe_to_cylinder9.ms`, `pipe_stub_segment_lo.ms`, `pipe_optimize_clone.ms`:
  три разных способа обработки, не одна безусловная кнопка.
- `mesh/clean_opening_grid.ms`: сначала показать лишние рёбра, затем убрать лупы.
- `Ground_Tools.ms`: очистка покрытий, точки на швах, построение рельефа.
- `Zamena_V2.ms`: замена повторяющихся объектов проверенным облегчённым образцом.

Ground-инструменты создают в том числе веерную/треугольную сетку; их нельзя
автоматически применять к quad-master BODY. В НПМ нужны отдельные режимы
«рабочая геометрия» и «экспортная копия».

### 3. Фасады → атлас → UV

- `projects/facade-atlas/maxscript/apply_atlas_uv.ms`: выбор фасадных полигонов,
  камеры, изоляция на рендере, пакетный рендер, применение `atlas.json` и карт.
- `projects/facade-atlas`: отдельное Python-приложение упаковки 2K атласа.
- `Maf Tools.mcr`: Render to Texture и измерение/изменение плотности как
  кандидаты для адаптации; UDIM-операции сюда без переключения профиля не переносить.

Фасадный и растительный атласы оставить разными действиями: у них разные
источники, работа с альфой и способ переноса UV.

### 4. Ground и растительность

- `FloraAtlas.ms`: сбор карт из выделения, обрезка по UV, упаковка,
  diffuse/opacity, перенос UV, назначение материала.
- Glue из `Maf Tools.mcr`: посадка по поверхности и смещение.
- `Ground_Tools.ms`: геодезические отметки → поверхность; исправление покрытий.
- `Zamena_V2.ms`: замена по имени; добавить выбор copy/instance и перенос
  проектных метаданных. Сейчас реализация использует `copy` и удаляет исходную цель.

### 5. Имена, материалы, выпуск

- Из `A101AGRLP.ms` выделить функции ОКС/Ground/Flora, стекла, назначения карт,
  поиска ошибок и FBX-экспорта.
- Из `AlexYo_AGR_renamerV2.ms` использовать подход к переименованию карт,
  переработав обработку общих материалов, расширений и конфликтующих имён.
- `zavod_fbx_prepare_mesh.ms`, `export_fbx_inventory.ms`,
  `zavod_fbx_uv_channels.ms`: адаптировать под единый контекст выпуска.

Последний скрипт записывает User Property `MapChannel:1 = UV`; он не делает
развёртку и не доказывает корректность UV. После экспорта нужен повторный импорт.

## Вкладка ВПМ

### 1. Геометрия и повторяемые действия

- `Poly Actions Copy_V6.ms`: внутри версия **7.6.0**, запись Extrude/Inset/MatID/
  Connect, пресеты и восстановление. Не выбирать версию только по имени файла.
- `mesh/edge_connect_segments.ms`, `select_coplanar_faces.ms`,
  `floor_trace_extrude.ms`, `clean_opening_grid.ms`: отдельные локальные операции.
- `Region_Cut.ms`: заполнение выделением области от выбранного полигона;
  название файла не означает универсальный геометрический Boolean Cut.

### 2. Материалы / UV / UDIM

- Из `Maf Tools.mcr`: UDIM по MatID, плотность GET/SET/Analyze,
  раскладка тайлов, ID Colors, запекание, разделение элементов по расстоянию.
- `Udim_Geo_Json.ms`: сборка preview-материалов и обновление назначений
  по UV-тайлам. Это часть просмотра и обратного импорта.
- `UDIM Viewer_V1.2.ms`: частично перекрывает этот модуль; оставить одну
  выбранную реализацию после сравнительного теста.
- `Texture_Zaglushki_Ground.ms`: отдельный генератор заглушек, с профилем
  размеров/каналов вместо общих констант.

ID материала и UDIM должны храниться явным соответствием: перестановка слотов
не должна незаметно менять назначение фасадных материалов.

### 3. Коллизии

Основной кандидат — `UCX_Tools.ms`: сечения здания, очистка контура,
разбиение невыпуклого контура, Detach с зазором, экструзия по уровням,
box/hull по выделенным граням. В реализации есть перевод миллиметров через
`units.decodeValue` и значение gap по умолчанию 2 мм.

`collision_splitter_ucx.ms` из zavod — дополнительный метод пространственной
сетки, после переработки перекрытий и отступов. Hull использует `nvpx`,
поэтому доступность MassFX/PhysX проверять до запуска.

`UCX_Check.ms` — кандидат для диагностики поверхностных пересечений,
но полноценный валидатор надо расширить: вложенные объёмы, компланарные
контакты, расстояния между компонентами, замкнутость и выпуклость.

### 4. Свет

`FreeSpot_Tools.ms`: создание по граням, анализ, предварительное цветовое
выделение, сокращение числа источников несколькими методами.
`Light.ms` и `Light_Metr.ms` — альтернативные простые варианты; сопоставить
на тесте единиц и направления света, затем оставить одну основу создания.
Именование Root/Spot/Omni и отдельный Light.fbx — самостоятельный этап
выпуска, его нельзя считать реализованным наличием генератора FreeSpot.

### 5. Комплект и обратная проверка

`Udim_Geo_Json.ms` импортирует модели с размещением по GeoJSON и строит
preview-материалы. Он не является готовым экспортёром GeoJSON.
Нужны отдельные реестр данных проекта, проверяемое преобразование координат,
публикация FBX/GeoJSON/PNG, упаковка и проверка извлечённого комплекта.
Обнаруженный `GeoAGR13.63/GeoAGR_start.ms` лишь загружает
`GeoScripts/GeoAGR.mse` из установки Max; возможности закрытого ядра здесь
не подтверждены чтением кода.

## Что требует исправления до объединения

1. **Ложная точность Collizii.** `Collizii.ms:144–160`: после bbox test
   создаются/удаляются mesh snapshots и возвращается true; теста треугольников нет.
   Нельзя маркировать этот результат «точное пересечение».
2. **UCX_Check не проверяет зазор.** `UCX_Check.ms:34–102` проверяет отрезки
   против треугольников; параллельный случай отклоняется. Полное вложение
   объёма без пересечения поверхностей таким методом не обнаруживается.
   `TOLERANCE=0.01` участвует в отборе кандидатов, а не измеряет минимальный зазор.
3. **Сеточный UCX с расширением.** `collision_splitter_ucx.ms:37–38,783–790`
   задаёт перекрытие и наружное расширение долями размеров. Это не допуск в мм.
4. **Плотность для одной карты.** `density.ms` использует 4096 и площадь
   в единицах сцены без явного перевода в метры. В `Maf Tools` уже есть
   `tdt_GetMeters` и передаваемый mapSize; это более подходящий кандидат.
   Всё равно проверить общий UV, масштаб объектов и различающиеся размеры карт.
5. **Заглушки фиксированы.** `Texture_Zaglushki_Ground.ms:142–146` пишет
   256×256; значения ERM фиксированы. Общая кнопка для обоих профилей
   должна учитывать тип карты и подтверждённые требования.
6. **Изменение рабочего объекта при подготовке.** `A101AGRLP.ms:893–1020`
   назначает новый Standard, меняет имя, pivot, слой, добавляет Reset/Triangulate.
   В общей тулзе эти действия выполнять на управляемой экспортной копии.
7. **Перезапись текстур.** `AlexYo_AGR_renamerV2.ms:25` вызывает File.Copy
   с overwrite=true. Два исходника с одним результирующим именем конфликтуют;
   нужен предварительный план имён и отдельная папка выпуска.
8. **Очистка метаданных конфликтует с хранением настроек.** `Maf Tools`
   использует `IDC_SavedData`; `ClearCustomAttributesAndObjProp_010.ms`
   умеет удалять CA/UDP. Нужен список сохраняемых проектных атрибутов,
   а агрессивную очистку переносить в экспортную копию.
9. **Несколько Flora Atlas.** Два `.mcr` регистрируют `macroScript FloraAtlas`,
   а Andrew-версия использует тот же rollout. Не загружать все варианты вместе.
10. **Undo недостаточно.** Копирование файлов, запекание и изменения `.cgeo`
    не покрываются обычным Undo сцены. Нужны версия результата и журнал файлов.

## Что оставить дополнительным

- `zavod_scene_optimizer.ms` и библиотеки proxy/maps/flora/forest: обслуживание
  Corona-сцены. Proxy-оптимизатор по документации перезаписывает `.cgeo` с backup;
  это не обычное облегчение экспортной копии меша.
- RAL Multi/Sub и SketchUp→Corona: подготовка/визуализация, а не универсальный
  материал сдачи. `assign_sm_standard_legacy_by_number.ms` привязан к конкретному проекту.
- `Interier_Box.ms`: заоконные боксы. В текущем проекте BODY без интерьера;
  автоматически включать этот инструмент в процесс нельзя.
- `cam_sun_batch.ms`, `master_scene_helper.ms`: вспомогательные рендеры.
- Copitor, Align, EdgeDistributor, MultiBridge, Vertex Cleaner: вспомогательные
  команды моделирования, без самостоятельного статуса проверки АГР.
- UVTools, генераторы окон/дверей, GeoAGR и другие MSE/бинарные продукты:
  внешние инструменты с проверкой установки и запуском доступного macro;
  наличие установщика в папке не означает установленную рабочую зависимость.
  Перед распространением общей тулзы нужно определить условия включения чужого кода.

## Устройство реализации

Первая версия — MAXScript-оболочка и адаптеры к выбранным исходникам.
Из больших rollouts выделить чистые функции обработки; общий UI не должен
просто открывать десяток прежних окон.

Каждая команда получает: профиль NPM/VPM, точный набор nodes, параметры,
каталог результата. Возвращает: обработанные/пропущенные объекты, созданные
файлы, ошибки и проверки. Сцена и её выделение не должны быть скрытым входом
для библиотечных функций. Глобальные имена перенести в пространство AGRWB.

Общий слой: единицы; пути; область; создание копий; имена; материалы;
диагностика; экспорт; реестр артефактов. Python применять там, где он уже
нужен для Facade Atlas/инвентаря и обработки пакета. UI первой версии может
оставаться целиком в Max. Конкретные API и библиотечные версии в этом обзоре
не выбирались; Context7 среди доступных инструментов не найден.

Все перечисленные разделы — предложение. Профили требований брать из
проверенных источников проекта; несовпадение со старым скриптом или чекером
не исправлять молчаливой заменой нормативов.

## Порядок сборки и проверки

1. Оболочка с двумя вкладками, областью и диагностикой зависимостей.
2. Один законченный НПМ-сценарий: выбранный фасад → камеры/атлас/UV → имена
   и материалы → экспортная копия → FBX и повторный импорт.
3. Один ВПМ-сценарий: UV/UDIM и карты → UCX с проверкой → комплект.
4. Подключить Ground/Flora, свет, пресеты геометрии и обратный импорт.

До интеграции изменяющих сцену модулей: отдельная тестовая сцена,
проверка загрузки `fileIn`, повторного открытия окна, Undo, отмены,
пустого/смешанного выделения, групп и инстансов. Для UV — метры/сантиметры,
2048/4096, общий UV и пограничный тайл. Для UCX — непересекающиеся тела,
пересечение, вложение, компланарный контакт, раздельные компоненты и зазор.
После выпуска — проверка реальных файлов и AGR Checker, ручные пункты отдельно.

Здесь нет заявления, что скрипты прошли эти испытания. Следующий шаг —
согласовать состав кнопок и сделать первый вертикальный сценарий на копии сцены.
