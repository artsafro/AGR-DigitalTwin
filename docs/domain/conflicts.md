# Conflicts and dubious rules

Keys: `reg p.N` = `Rasporyajenies19012026trebovaniya(2).pdf` page N (read by me unless noted). `local:` relative to the repo root (AGR knowledge base; AGR `docs/` lives in `docs/agr/`). No side is chosen here.

Decided items keep their text and carry a **Decided** note; the YAML `conflicts:` entry for them is `status: noted`. Checker references: SINTEZ AGR Checker v1.6.1 (`scripts/autochecks/check_utils.py`, `hp_checks.py`, `constants.py`), installed under `%APPDATA%\Blender Foundation\Blender\4.4\extensions\user_default\sintez_agr_checker`.

## A. Inside the regulation
1. VPM triangle limits: table = OKS 1 000 000 / Ground stepped up to 4 500 000 (reg p.28-29 §3.9-3.10) vs figure 2.1 = OKS <= 800 000, Ground <= 3 000 000 per FBX (reg p.40, image-verified). Local proposal: table wins, review until customer confirms (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#13). **Decided 2026-10-07 (user):** table is the hard limit (1 000 000 OKS; Ground by area), as the checker. Project target: <= 150 000 triangles per OKS FBX in VPM as in NPM, so one model serves both; if impossible, windows become atlas textures on planes.
2. GeoJSON mandatory fields: all OKS values except `other` mandatory (reg p.27 §2.6) vs table allows empty FNO_code / act_AGR "if no information" (reg p.53-54). YAML says fail_except_other (local: standards/VPM_STANDARD.yaml#geojson) vs ADR: review, never invent (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#1). **Decided 2026-10-07 (user): as the checker** - OKS `FNO_code` mandatory (3/6/9 digits from the FNO classifier), `act_AGR` may be empty; never invent values.
3. UCX triangle budget: <50k -> 15 000, else ceil(5%) (reg p.36-37 §13.7) vs "up to 100 000 additional" when model hits its limit (reg p.37 §13.8). YAML: apply stricter (local: standards/VPM_STANDARD.yaml#collision); ADR: not approved, review; boundary 49 999/50 000 untested (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#2). SINTEZ implements own 15k/5%/100k mix (local: docs/agr/decisions/ADR-0004-reuse-installed-toolchains.md). **Decided 2026-10-07 (user): checker formula** - < 50 000 -> 15 000, else min(ceil(5 %), 100 000).
4. NPM ground density unit: "10-40 pixels per square metre" vs example 2048 px <-> 204 m square = ~10 px per linear metre (reg p.10 §6.1). YAML literally `px_per_square_meter` (local: standards/NPM_STANDARD.yaml#textures); ADR forbids auto-check until clarified (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#8). Jobs used 10-40 px/m linear (AGR Checker bounds) (local: jobs/GROUND-PROJECTION/NPM_RESULT.md; local: docs/agr/case_studies/GROUND_CONTOURS_AND_NPM.md).
5. Placeholder size: NPM 128x128 (reg p.3-4) vs VPM 256x256 (reg p.22, p.31 §3.1). NPM allowed sizes list 256-2048 (reg p.9 §5.2) has no explicit 128 exception except "except placeholders" (§5.9). NPM YAML omits 128 (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#9). Max tool writes 256 placeholders for both profiles (local: docs/agr/research/max-workbench/REVIEW.md#5). **Decided 2026-10-07 (user), as the checker:** NPM placeholders 128x128, one colour, only for Metallic/Roughness; VPM placeholders 256x256. The 3ds Max tool writing 256 for NPM must be fixed.
6. Normal map Y: NPM definition Y -1..+1 -> G 0..255 (OpenGL-like, reg p.3) vs VPM Y +1..-1 -> G 0..255, explicitly DirectX (reg p.23, p.30 §5.1.7). NPM convention never named -> dubious. **Decided 2026-10-07 (user):** NPM deliveries carry no normal map (optional per reg p.9), so the convention does not arise. Revisit if an NPM normal map is ever needed.
7. Two-sided alpha planes: NPM forbids thickness/duplicated offset polys on opacity geometry (reg p.8 §3.13) vs VPM requires duplicate offset 0.003-0.01 m with flipped normal (reg p.36 §12.3). Profile-specific, but tools shared between profiles must branch.
8. Alpha: NPM alpha channel forbidden, separate opacity map allowed (reg p.9 §5.5, §5.8) vs VPM alpha in Diffuse allowed for cut-outs, ERM/Normal no alpha, MainGlass no maps (reg p.30, 32, 36).
9. UDIM figure typo: 1078 repeated instead of 1079 (reg p.39) vs text "sequential 1001-1100" (reg p.23, 31). Local interpretation: text wins (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#5).
10. Texel density formula: OCR text layer shows "+" vs image shows division L_t / L_p (reg p.32, image-verified by me and local: docs/agr/decisions/ADR-0002-source-discrepancies.md#12).
11. Material slot boundary: extra slots when > 100 UDIM maps, forbidden to split when < 100 maps (reg p.30 §4.3-4.4): exactly 100 undefined; "maps" vs "tiles" ambiguous (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#10).
12. MB/GB decimal vs binary undefined (reg p.6, 9, 26); YAML uses decimal bytes (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#4). **Decided 2026-10-07 (user): binary units, as the checker** - 1 GB = 1024 MiB, 500 MB = 500 MiB, 3 MB = 3 MiB.
13. Glasses GeoJSON: described as "array" (reg p.55 §22) but example uses an object keyed by material name when glass exists, `[]` when absent (reg p.51-53). Also OCR on p.51 reads "G]asses" - key spelling must be `Glasses`. **Decided 2026-10-07 (user), as the checker:** `"Glasses": []` without glass, else a list with one object keyed by glass material name; names match the FBX glass materials; identical glasses must be one material; metallicity 0.84 recommended (0.7-0.9).
14. VPM scene cleanup list omits lights (reg p.24) whereas NPM explicitly removes lights (reg p.4); VPM lights belong only in separate Light FBX (reg p.33, 37-38). **Decided 2026-10-07 (user), as the checker:** lights only in `SM_<Address>_Light.fbx`; any non-mesh object in the main FBX fails.
15. UCX gap 0.02-1 cm is only "recommended" (reg p.36 §13.4) - YAML stores as `recommended_gap_cm` but must not become blocking (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#3). Andrew UCX tool default gap 2 mm (local: docs/agr/research/max-workbench/REVIEW.md#3) lies inside 0.2-10 mm - consistent; GeoAGR ucx_check treats face contact (0 gap) as a finding (local: docs/agr/inventory/GEOAGR_13_63_REVIEW.md).

## B. Regulation vs local YAML / docs
16. NPM page range: brief says App.1 = PDF pp.1-19 (local: docs/agr/DIGITAL_TWIN_AI_PROJECT_BRIEF.md#1) vs NPM_STANDARD.yaml `pdf_pages: [1..13]` (figures pp.14-19 not referenced). Minor.
17. NPM glass material names `M_Glass_01..07` (reg p.13 §3.5) missing in NPM YAML; YAML material mask only for opaque (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#9).
18. Flora opacity "if needed" (reg p.10 §5.13) vs YAML `vegetation_maps: [diffuse, opacity]` may read as both mandatory (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#9).
19. VPM pivot: regulation = pivot at geometric center X/Y of model, Z = project zero (reg p.32-33 §9.4, image-verified) vs YAML only `per_fbx_local_origin_xyz [0,0,0]` + `project_zero_elevation` (local: standards/VPM_STANDARD.yaml#positioning) - geometric-center rule absent from YAML. **Decided 2026-10-07 (user), as the checker:** Main origin at FBX 0,0,0; bbox centre X/Y within 10 % of the size from the origin; all meshes share the origin within 1 mm (UCX exempt); Z = project zero; MSK-77 point in GeoJSON.
20. YAML incomplete for: Address `_001` index for free-standing buildings (reg p.26 §3.7), alpha-plane offset (p.36 §12.3), lighting FBX rules (p.37-38), GeoJSON length/mask/precision limits (p.53-55) (local: docs/agr/decisions/ADR-0002-source-discrepancies.md#11). **Decided 2026-10-07 (user):** encode as the checker plus regulation limits - `_NNN` only with more than one OKS; GeoJSON types/required/decimals from the checker table and lengths from reg p.53-55; alpha-plane offset 0.003-0.01 m; Light FBX: point/spot only, `_Omni`/`_Spot`, numbering per type from 001. Implementation: backlog Q6.
21. NPM textures: YAML `alpha_channel: forbidden` (reg-consistent) vs accepted project atlases saved as RGBA PNG with AC-front perforation in alpha (local: docs/agr/case_studies/GLB_B_MAIN_ATLAS.md; local: docs/agr/case_studies/GLB_A_MAIN_ATLAS.md). Dubious for NPM delivery: would violate reg p.9 §5.5 unless split into separate opacity map. **Decided 2026-10-07 (user), as the checker:** no alpha in any NPM image; diffuse RGB, opacity as a separate `_o_` map. Accepted GLB RGBA atlases must be converted before delivery.
22. NPM texel density for OKS: regulation exempts OKS (reg p.10 §6.2) vs earlier project iteration applying 10-40 to OKS (rejected later, local: docs/agr/decisions/OBR22_NPM_SCALE_V012.md). Resolved locally; keep as pitfall.

## C. Between local sources (project decisions/lessons)
23. 24. Window seating: fixed 10 mm overlap past opening edges, plane at mid-reveal (local: jobs/GLB-NPM/CLEARANCE_RULES.md) vs "measure seating per window; 10 mm embed does not define seating, do not invent" (local: docs/agr/GEOMETRY_RULES.md; local: jobs/OBR22-K02/STATE.md).
25. Glass/infill recess: 30 mm behind frame face (local: jobs/REVIT-OPENINGS/outputs/openings-v003/README.md) vs 35 mm with 10 mm glass-edge grip, 40 mm frame face, 80 mm depth (local: jobs/MASHI-LP/MASTER_DIRECTIVE.md).
26. VPM cut size: quads < 4x4 m (local: docs/agr/GEOMETRY_RULES.md) vs adapter default 3.9 m (local: docs/agr/ADAPTER_EXTRACTION.md) vs MASHI < 3.8 m (local: jobs/MASHI-LP/MASTER_DIRECTIVE.md). **Decided 2026-10-07 (user):** cut quads to about 4 x 4 m for the target 1024 px/m (one 4096 tile = 4 m); adapter default 3.9 m leaves room for padding. General form: max_side = (tile_px - 2 x padding_px) / density_px_per_m.
27. VPM texel density targets: 514 px/m (OBR22 v009) / 1024 (OBR22 v011) / 550-1500 (SOSH1150 user range) / 1500 initial; all inside or overlapping regulation 512-1706 except 1500 fixed target which caused closure failures (local: jobs/OBR22-K02/STATE.md; local: docs/agr/case_studies/SOSH1150_CONTINUOUS_WALL_UV_FBX.md).
28. NPM-OKS raster: 39.9 px/m (OBR22 v011) -> 96 px/m (v012) vs 80 px/m (FACADES) vs ~42.5 (v010); all "not a norm" (local: docs/agr/decisions/OBR22_NPM_SCALE_V012.md; local: jobs/FACADES-ATLAS/STATE.md).
29. Padding: NPM 8 px (reg min) / facade bands 16 px / continuous walls 20 px wrap on 4096 (below reg 32 px min for 4096 if treated as VPM!) / VPM 32 px (local: jobs/UV-CONTINUOUS/STATE.md; local: docs/agr/case_studies/SOSH1150_CONTINUOUS_WALL_UV_FBX.md). Dubious: SOSH 4096 map with 20 px padding vs reg p.30 §5.1.5 >= 32 px.
30. Overlap/clearance tolerances: 5 mm (GLB parallel faces), 2 mm (MASHI coplanar), 5 um (OBR22 intersection) - different test purposes. Regulation: 5 mm-2 cm spacing, 0.002 m duplicate tolerance (reg p.8, 29).
31. Panel module sizes: 1600x1200/1200x1600 replaced by 1200x600 (brick) and 600x1200 (FACADES v005); panel joint 5 mm included in module = unconfirmed assumption (local: jobs/FACADES-ATLAS/STATE.md).
32. Reveals: no extra reveal geometry, recolor existing faces (local: jobs/GLB-NPM/CLEARANCE_RULES.md) vs v023 added 154 reveal quads (rejected by user) (local: jobs/GLB-NPM/TOWER_STAGE_V023.md).
33. One UDIM per texture ID (local: docs/agr/UV_RULES.md, project) - not a regulation rule; regulation only requires sequential tiles and no slot split < 100 maps. Brief explicitly warns not to derive UDIM from MAT number (local: docs/agr/DIGITAL_TWIN_AI_PROJECT_BRIEF.md#4). Compatible but easy to misread.
34. SOSH1150 FBX hand-off embedded a UDIM-named diffuse (`T_Template_Address_001_Diffuse_FlipH_v005.1001.png`) - neither NPM (atlas name) nor VPM (external PNG, `T_Address_Diffuse_1.1001`) compliant; work hand-off only (local: docs/agr/case_studies/SOSH1150_CONTINUOUS_WALL_UV_FBX.md).
